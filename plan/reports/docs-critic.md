# Exploration report: critical docs review

Reviewer run on 2026-09-25 against origin/main 6f8100a. Owner's brief: mention the fork once (in the README credits), present the package on its own terms, and flag confusing or self-defeating statements such as the "Undici interceptor app … upstream nestjs-undici … raw body stream" note on the benchmarks page.

## Top 10 problems

1. **The benchmark note is wrong and self-defeating.** docs/benchmarks.md:62 is generated by generate-comparison-report.js:486. It says the plain undici app "returns the raw body stream", but `apps/nestjs-fastify-undici/src/app/app.service.ts` does `await res.body.json()`. The note also contradicts generator:232-234. The "Interceptor Overhead" table divides numbers from two different libraries, so its +148% looks like our interceptors are slow. **Fix:** delete the table and the note, and use a like-for-like "With an interceptor" table instead (see the benchmarks section below).
2. **The benchmark summary compares the wrong library.** docs/benchmarks.md:9-11 says "Undici is 67-70% faster than Axios", but that row is upstream nestjs-undici. "67% faster" really means 67% lower latency. The interceptor sentence puts our package with an interceptor against axios without one. **Rewrite (generated):** "**nestjs-axios-undici serves 2.0-2.3x the requests/s of @nestjs/axios, with 51-56% lower average and 54-58% lower p95 latency.** Same NestJS app, same interceptor, only the import changed."
3. **The README headline numbers are typed by hand and stale.** README.md:16 says 1.9-2.5x, 48-60% and 54-62%. The current data gives 2.0-2.3x, 51-56% and 54-58% for Fastify, and 1.7-2.7x for Express. migration-guide.md:319 repeats the stale numbers. "Same logging interceptor on both sides" isn't literally true: one app uses axiosRef interceptors, the other a native class interceptor. **Fix:** generate the headline into the README between `<!-- bench-headline -->` markers, and keep only a link in the migration guide.
4. **The Features page is framed around the fork.** docs/features.md:3 ("started as a fork… tracks upstream… v0.2.60") and :11-24 (a comparison table against nestjs-undici). **Fix:** delete the page.
5. **"Drop-in" hides real differences.** README.md:17 and :40 say "existing calls… keep working", but:
   - redirects are only followed when `maxRedirects` is set (axios follows up to 21);
   - axiosRef interceptors run in reverse order;
   - unsubscribing doesn't cancel the request.

   **Fix:** a "3 differences" box in the README (these will shrink as the compat fixes land).
6. **The Configuration guide describes the package before axios compatibility existed.** configuration.md:3/5/9 frame it as undici options, :20 recommends a module-wide `Content-Type: application/json`, and :120-130 is filler about env vars. **Fix:** rewrite the opening, drop the Content-Type default and drop the env-var section.
7. **The migration guide opens with the package rename.** migration-guide.md:5-27 starts with "Coming from nestjs-undici-interceptors". **Fix:** move it to the end as "Upgrading from nestjs-undici-interceptors (0.5.x)", in 5 lines.
8. **The migration guide is long and repeats other pages.** :63-156 ("Key Features for Migration" 1-5), the :321-338 summary, and marketing lines. **Fix:** cut it to about 120 lines: Change the import → Differences to check → Run side by side → OpenTelemetry and interceptors → Upgrading from the old name.
9. **The migration guide gives wrong or risky advice.** :269-287 says to use interceptors for transforms, which contradicts axios-supported-options.md:101 (module-level transforms are supported). :242-253 recommends `pipelining: 10`, which is unsafe for non-idempotent requests. **Fix:** say which transforms are supported, and recommend only `connections: 100` (link undici's docs for the rest).
10. **The benchmarks README is stale and confusing.**
    - The title "Fastify vs Express vs Undici" mixes a framework with a client.
    - It shows 311-348% while the docs page shows 211-248% for the same data.
    - The diagram shows 3 apps on ports 3002-3004, but there are 7 containers on ports 3011-3037.
    - The durations contradict each other.
    - It lists 3 of the 6 apps.
    - The k6 "Expected output" example is stale.

    **Fix:** turn it into a how-to-run page of about 100-150 lines.

## Benchmark presentation

**Fairness problems:**
- The headline and summary rows measure another library.
- There is no nestjs-axios-undici row without an interceptor.
- The two interceptor apps use different interceptor styles.
- The undici app calls `request(url)` instead of `get(url)`.
- About 10 Nest `Logger.log` lines per inbound request dominate the interceptor rows.
- The run order is fixed.
- Absolute milliseconds differ about 2x across Node versions. Lead with ratios instead.

**Apps:** use one shared app source, with `CLIENT=axios|undici` choosing which package `HttpModule` and `HttpService` are imported from, and `PLATFORM=express|fastify`. The service code is then byte-identical: `httpService.get(url)` and `res.data`. Rows:
- Express · @nestjs/axios vs Express · nestjs-axios-undici. Express is the Nest default, so this is the primary pair.
- Fastify · @nestjs/axios vs Fastify · nestjs-axios-undici.
- With an interceptor: both clients on Express (Fastify optional), using identical `axiosRef.interceptors` code that adds a header and times the call, with no stdout logging. Optionally add a native-interceptor row for this package only.

Drop `nestjs-fastify-undici` and the `*-interceptor` app directories, and drop the off-topic "Fastify vs Express" findings.

**Headline (generated):** "Same NestJS app, only the import changed: **nestjs-axios-undici served N.N–N.Nx the requests/s of @nestjs/axios with NN–NN% lower p95 latency** (Express and Fastify, Node.js 22/24/26)." Write "x throughput" or "% lower latency", never "% faster".

**Page structure:**
1. Headline
2. Ratio table (platform × with/without interceptor)
3. Chart for the latest Node version
4. What's measured: 3 bullets plus links to the app source
5. Full results per Node version
6. Regression check
7. Reproduce
